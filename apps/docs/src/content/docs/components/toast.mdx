A toast confirms something that just happened ("Saved", "Link copied") without getting in the
way: frosted glass at the bottom center that goes away on its own, and waits while the pointer
or focus is on it. Make one with `toast()`.

## Usage

<CodePanel>

```ts
import { toast } from '@glass-midas/components';

toast('Saved');

toast('Page deleted', {
  action: { label: 'Undo', onClick: () => restore() },
  duration: 6000,
});
```

</CodePanel>

Toasts stack at the bottom center, newest last, three at most: a fourth pushes the oldest out.
With a `key`, they don't stack: a toast whose key is already on screen updates that one (its
message and action) and starts its time again. Use it for things that add up while they happen:

```ts
let saved = 0;
function onSaved() {
  saved += 1;
  toast(`${saved} saved`, { key: 'saved' }); // one toast, counting, not one per file
}
```

Their region is announced politely to screen readers, so the message is read without
interrupting.

## Anatomy

- **`.gm-toasts`** is the region at the bottom center, created on the first toast.
- **`gm-toast`** is each message, on glass, with its action as a [chip](/components/chip/).

## Best practices

- **A few words**, about something the person just did.
- **One toast for a stream of the same thing**: give them a `key` instead of stacking a dozen
  «1 file saved».
- **An action only when it's useful right now**, like Undo; anything important needs a
  [dialog](/components/dialog/) instead, since a toast can go unnoticed.
