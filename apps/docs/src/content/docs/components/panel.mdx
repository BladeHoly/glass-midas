Glass can't sit inside glass: a surface's `backdrop-filter` hides the page from any glass inside it.
So a block that holds a segmented control, a select or a quantity can't be a `gm-surface`. A panel
is that block: a translucent fill with a hairline rim, so what's inside can still be glass.

## Usage

<CodePanel>

```html
<section class="gm-panel" aria-labelledby="options">
  <header class="gm-panel-header">
    <h2 id="options">Options</h2>
    <div class="gm-panel-actions">
      <button class="gm-chip gm-chip-plain">Reset</button>
    </div>
  </header>
  <gm-segmented aria-label="Quality" value="max">…</gm-segmented>
</section>
```

```css
/* A light theme: a lighter fill and a darker hairline. */
:root[data-theme='light'] {
  --gm-panel-fill: rgb(255 255 255 / 0.55);
  --gm-panel-rim: inset 0 0 0 0.5px rgb(24 20 14 / 0.14);
}
```

</CodePanel>

It's in `css/panel.css`.

## Best practices

- **Surface or panel?** If nothing inside is glass, use a `gm-surface`: it's the real thing. Reach for
  a panel when it holds glass (a segmented control, a select, a quantity, a dialog's trigger is fine
  either way).
- **One heading per panel**, in the header, so the page reads as a list of named blocks.
