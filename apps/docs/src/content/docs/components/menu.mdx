`<gm-menu>` is a [popover](/components/popover/) of actions: buttons and links, with a droplet
of glass under the one in focus. Opening it focuses the first item, the arrow keys move through
them, and picking one fires `gm-select` and closes the menu.

## Usage

<CodePanel>

```html
<button popovertarget="actions">More</button>

<gm-menu id="actions">
  <button value="rename">Rename</button>
  <button value="duplicate">Duplicate</button>
  <hr />
  <button value="delete">Delete</button>
</gm-menu>
```

```ts
menu.addEventListener('gm-select', (e) => run(e.detail.value)); // 'rename'
```

</CodePanel>

Links inside follow their `href` as links do. Icons go inside items, before the text.

### Items that change

A menu can be built or changed after it's on the page (the screens connected now, the recent
files): items added, removed or hidden are picked up on their own, so the arrow keys and
`gm-select` always see what's shown. A `.gm-menu-label` names a group without being an item.

<CodePanel>

```html
<gm-menu id="put-on">
  <span class="gm-menu-label">Put as background on</span>
</gm-menu>
<script type="module">
  const menu = document.getElementById('put-on');
  for (const screen of await screens()) {
    const item = document.createElement('button');
    item.value = screen.id;
    item.textContent = screen.name;
    menu.append(item); // picked up on its own
  }
</script>
```

</CodePanel>

## Anatomy

- **The host** is the glass and the popover, with `role="menu"`.
- **Each `button` or `a`** inside becomes a `menuitem`; an `<hr>` becomes a separator.
- **`.gm-droplet`** is the glass under the item in focus, following the pointer and the keys.

## Best practices

- **Actions, not navigation trees.** Keep it to one level and a handful of items.
- **A choice that stays visible** (a model, a mode) can live in a menu whose button shows it, as
  above. For two to four always-visible options, use [segmented](/components/segmented/).
