`@glass-midas/components` turns the core into ready-made elements. They're **Web Components** in
the light DOM, so they work in plain HTML and in any framework, and your CSS reaches inside them.
This site is built with them: the search box, the sidebar, the table of contents, every code
block, callout and tab group.

## Setup

Import the package once to register every element, and load its stylesheet with the tokens:

```ts
import '@glass-midas/components';
import '@glass-midas/components/styles.css';
import { tokensToCss } from '@glass-midas/core';

document.head.insertAdjacentHTML('beforeend', `<style>${tokensToCss()}</style>`);
```

Then write them as HTML:

```html
<gm-callout type="tip" heading="Hello">
  <p>This box is glass.</p>
</gm-callout>
```

Elements render on the server as their plain markup, and come to life when the script runs.
Importing the package during server rendering is safe; it defines nothing there.

### Only what you use

Each component is also its own entry: importing it registers that element alone, and its
stylesheet comes as the base plus one sheet.

```ts
import '@glass-midas/components/menu';
import '@glass-midas/components/css/base.css';
import '@glass-midas/components/css/popover.css';
```

| Entry                                  | Its sheet (after `css/base.css`)  |
| -------------------------------------- | --------------------------------- |
| `surface`, `button`, `callout`, `code` | `css/<same name>.css`             |
| `tabs`, `segmented`, `nav`, `search`   | `css/<same name>.css`             |
| `scrollbar`, `tip`, `dialog`, `toast`  | `css/<same name>.css`             |
| `popover`, `menu`                      | `css/popover.css`                 |
| `slider`                               | `css/slider.css`                  |
| `select`                               | `css/field.css`, `css/select.css` |
| `otp`                                  | `css/otp.css`                     |
| fields (`.gm-field`, `.gm-input`)      | `css/field.css`                   |
| checkboxes, radios (`.gm-check`)       | `css/check.css`                   |
| chips (`.gm-chip`)                     | in `css/base.css`                 |
| toggles (`.gm-toggle`), no script      | `css/toggle.css`                  |

The sheets sit in cascade layers (`gm-base`, `gm-components`, `gm-overrides`), so they work in
any order, and any CSS of yours outside a layer wins over them. Each entry stays under its own
size budget; the whole package is every entry together.

## Glass options are attributes

Every component accepts the core's [options](/reference/core/#glassoptions) as attributes, in
kebab case:

```html
<gm-surface radius="28" thickness="60" bezel="30" ior="1.33" light-angle="-120">…</gm-surface>
```

Large surfaces that sit still, like callouts and code blocks, use the `blur` tier by default:
refraction would cost more there than it shows. Add `variant="full"` to refract anyway, or
`variant="lite"` to make any component blur. Components never step **up** a tier, so a browser or
user that needs `solid` still gets it.

## Materials

Glass is **clear** by default: it shows the backdrop and bends it at the rim. Add
`material="frost"` to frost it heavily under a smoke tint, for glass that carries text over a busy
background. Both keep the same rim. See them side by side on the
[Surface](/components/surface/#materials) page.

## Styling

The stylesheet uses only custom properties, inside `:where()`, so any selector of yours wins
without a fight. Set the [tokens](/concepts/tokens/) and these to theme every component:

| Property              | Use                                       |
| --------------------- | ----------------------------------------- |
| `--gm-ink`            | Text on glass.                            |
| `--gm-ink-muted`      | Secondary text, inactive tabs and links.  |
| `--gm-rim`            | The hairline edge of every surface.       |
| `--gm-lift`           | The shadow under every surface.           |
| `--gm-focus`          | Keyboard focus ring.                      |
| `--gm-callout-<type>` | Accent of each callout type.              |
| `--gm-frost-tint`     | The smoke tint of frost glass.            |
| `--gm-chip-fill`      | Chip fill; `-hover` and `-on` for states. |

## With React

React 19 can use the elements directly. For React 18 too, and for typed props and events,
`@glass-midas/react/components` wraps each one: `<GlassSearch source={…} onSelect={…} />`. See
the [React reference](/reference/react/#components).

## Glass inside glass

A `backdrop-filter` on an element hides the page from any glass inside it, which then only sees
its parent. Don't put glass components inside another glass surface: give the container a plain
translucent background instead, as this page's article does.
