A skeleton stands where content will appear, in its shape, so the page doesn't jump when the
content arrives. Pagination moves between pages: chips, with the current page on.

## Usage

```html
<div aria-busy="true" aria-label="Loading orders">
  <span class="gm-skeleton gm-skeleton-text" style="width: 60%"></span>
  <span class="gm-skeleton gm-skeleton-text"></span>
</div>

<nav class="gm-pagination" aria-label="Pages">
  <a class="gm-chip gm-chip-plain" href="?page=1" aria-label="Previous page">‹</a>
  <a class="gm-chip" href="?page=2" aria-current="page">2</a>
  <a class="gm-chip gm-chip-plain" href="?page=3">3</a>
</nav>
```

The current page is a chip that's on: `aria-current="page"` gives it the fill and the rim.

## Best practices

- **Shape skeletons like the content**: the same number of lines and the same widths, roughly.
- **Mark what's loading** with `aria-busy="true"` on its container, and swap it in at once.
- **Skip skeletons for quick loads.** Under about 300ms, a flash of skeleton is worse than a pause.
- **Say where you are:** "21–40 of 214" next to the pages.
